Sparkbox storage and sync today

Two full copies of the vault, joined through Google Drive. Only Obsidian moves files between them.

Where it breaks

  1. "Added" in Sparkbox confirms a local write only. The capture has not left the phone.
  2. GSync has no background service. Captures wait until Obsidian is active on Android.
  3. Drive holds whole files with no merge. On 5 Nov 2026 the Android inbox was 7,645 bytes and the Mac and Drive inbox 5,813 bytes, and a manual merge fixed it.
  4. Inbox.md has several writers: Sparkbox, Telegram, and agents that empty it. Each copy can change before the other arrives.

How Notion and Obsidian Sync do it

Both keep a copy on each device and use one always-on service built for syncing. The service tells devices what changed, so they do not need to re-scan every file.

Notion: a database of small pieces

  1. Devices keep pages in a local SQLite store.
  2. When Notion applies updates, the server sends a message on that page's channel.
  3. Devices listening to that page fetch its latest changes.
  4. After being offline, devices re-fetch only pages with a newer server version.
  5. Offline-enabled pages use a CRDT, a data format built to combine edits from several devices.

Obsidian Sync: files, with a dedicated sync service

  1. Your notes stay as files on each device.
  2. Obsidian's own service carries changes and keeps version history.
  3. When two devices change a Markdown note, it merges them with diff-match-patch.
  4. Other file types use "last modified wins".
  5. You can choose a conflict copy instead of auto-merge on each device.
  6. Forum reports say sync runs only while the mobile app is in the foreground. This is not official documentation.

The main lesson

The speed comes from a sync service that knows exactly what changed, plus a clear rule for clashes. Google Drive stores your files, but GSync must still find changes and has no merge rule.

Small sync service: draft spec

Goal: a capture reaches every device without opening Obsidian, and Obsidian on Android stays your editor. Status: for review. Nothing is built.

Data

files(path PRIMARY KEY, version, hash, size, deleted, device, updated_at)
counter(n)                      -- one row, rises on each commit
R2: blobs/<sha256>              -- never overwritten

API

GET  /changes?after=N           files with version > N, paged
GET  /blobs/:hash               file contents
PUT  /blobs/:hash               upload contents, checked against the hash
POST /commit                    {path, baseVersion, hash, deleted}
                                200 {version} or 409 {current version and hash}

Core logic

-- /commit: one D1 batch. A rejected write only leaves a gap in the counter.
UPDATE counter SET n = n + 1;
INSERT INTO files (...) VALUES (..., (SELECT n FROM counter))
ON CONFLICT(path) DO UPDATE SET hash = excluded.hash, version = excluded.version, ...
WHERE files.version = :baseVersion;
-- No row changed: return 409.
  1. Each client remembers the version and hash it last synced for every path.
  2. Pull: get changes after the last seen version. If the local file still matches its remembered hash, replace it.
  3. Local file also changed: keep the server file at the path, and save local text as Note (conflict Android 2026-11-08 2224).md.
  4. Push: send each file whose hash differs from the remembered hash.
  5. 409: pull, then repeat.
  6. Inbox.md append: read latest, stop if the entry already exists, append, commit. On 409, repeat. This is safe after retries and crashes.
  7. No echo: a client records the new hash before writing a pulled file, so its watcher ignores that write.
  8. Delete and rename: delete sets a flag. Rename is a delete plus a create. Android moves pulled deletes to trash with trashFile.
  9. Never synced: .git, .obsidian, .claude, .agents, .serena, .env, .DS_Store.

Must pass on a test vault

  1. Capture with Obsidian closed reaches the Mac.
  2. Capture during Process inbox loses neither change.
  3. Same note edited offline on both devices keeps both texts.
  4. Sync stops mid-upload, then resumes without damage.
  5. Delete, rename and 4 MB photo sync correctly.
  6. Mac sleeps for a day, then catches up.
  7. Full vault hashes match on Mac, Android and server.

Rollout

  1. Zip the vault. Keep Drive frozen as backup.
  2. Build server and Mac agent on a copy.
  3. Add the plugin on a test vault.
  4. Add Sparkbox behind a Settings switch.
  5. Run the tests above.
  6. Turn GSync off on both devices, then load the real vault.

Check before building

Correction: I said Self-hosted LiveSync likely needs CouchDB. Its README also lists S3 and R2 object storage, with periodic or on-save sync. Its stored data is journal-based, so Sparkbox could not simply add a file. VaultDatum is another self-hosted Obsidian sync project, and I have not assessed it. Review both for one hour before committing to this build.

Decisions for review

  1. Should Daily and Health sync through Cloudflare? Android Obsidian needs them if you edit them there. This spec assumes yes, with TLS and provider encryption, not end-to-end encryption.
  2. Is a 30-second delay acceptable? Live push can come later.
  3. Is a conflict copy acceptable for notes, rather than auto-merge?
