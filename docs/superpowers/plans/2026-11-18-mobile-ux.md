# Sparkbox mobile experience

Android first · 18 November 2026 · baseline 1.11.0, commit `826efc9`

A reader saves an article between two meetings. Tomorrow they remember why it mattered but forget its title. Sparkbox earns a place on their phone if they can capture it in seconds, find it in their own words, and get back to the passage that mattered. A good review session starts from that same material.

## Evidence and design direction

The USB phone ran version 1.11.0 in dark mode. Direct inspection covered the populated home stream, capture chooser, a capture detail, vault browser, review picker, Scout landing, Profile, Settings and Dashboard. The remaining routes below were inspected in source. This is an expert walkthrough on an established vault. First-time comprehension, one-handed comfort, and speed improvements need participant tests. The Android project contains the implementation. iOS guidance informs a future client.

Keep the slate and emerald system in `Ui.java` and `SparkTheme.kt`. Use the system sans for navigation and reading, with 16sp/24sp for body copy and 14sp/20sp for supporting text. Start layouts at 16dp margins and 8dp between related controls. Dark surfaces use #0F141B and #171C23, with #F1F5F9 text and #10B981 accent. In light mode use #F8FAFC, #FFFFFF, #0F172A and #047857. Reserve warning colors for conditions that need attention.

The signature element should be the reader’s own reason for saving a source. For example, a sample article titled “Why streets cool after sunset” could carry the reader’s line “Compare with my evening walk.” Show their words beside the source identity, then offer a path to their connected notes. Never synthesize a personal reason when the field is empty.

## Screen decisions

| Surface and implementation | Evidence and decision |
|---|---|
| Shell, tab switching and Back · MainActivity | The previous shell cleared detail stacks on tab changes and animated the Spark icon every nine seconds when reviews were due. Delivered descriptive Library and Review tabs and removed the animation. Tab switches now retain routes, list position and search while the activity stays alive. Test returning from Scout to the exact source. |
| First run, empty library and filters · FeedView, FeedScreen, VaultActivity | A connected empty library offered a rescan. Empty filtered results used the same invitation. Delivered separate actions for choosing a vault, making a first capture and clearing a filter. Library explains folder access before the system picker. Onboarding with a disposable Obsidian vault was exercised on Android 15. |
| Library, search, bookmarks and file browser · FeedView, FeedScreen, VaultActivity | Source initials, status, thumbnail, summary and action footer competed for space. Browse lived in overflow. Delivered a labeled Capture action, direct Browse and more space for source names. The stream now leads with the title and gives the saved reason a distinct reading block. Keep keyword search immediate, preserve the active filter when semantic results arrive, and expose folders and bookmarks without duplicating search engines. |
| Share, quick note, voice, destination and widgets · ShareActivity, QuickActivity, QuickView, DestinationPicker, QuickTile, CaptureWidget, InboxWidget | Keep share-and-return and the separate recording Stop action. Keep Inbox as the fast default. Next test whether “Save to” is visible with the keyboard open and make the confirmation name the actual destination. Test a shared PDF, multiple files, offline voice, permission denial and interruption on disposable data. |
| Capture detail, processing, retries and map · CaptureScreen, CaptureMapScreen, FeedScreen | Preserve the distinction between a local copy, verified vault write and completed processing. Show one current state with its next action first. Put stage history and diagnostics behind Details. After processing, lead with Open note and make added topics navigable. Keep retry, uncertain-write inspection and attachment-only outcomes distinct. |
| Sources, topics, people, generic reader and full editor · UnitScreen, TopicScreen, VaultActivity, NotesListScreen, NoteEditorScreen, PageView | Keep source attribution, linked notes, personal annotations, raw Markdown, conflict checks and draft recovery. Delivered larger shared reading type and consistent Review actions. Next group the source’s claims separately from “My ideas”, move editing tools to one predictable location, and return citation readers to the passage they left. |
| Review picker and study · SparkView, SparkScreen | The gradient surprise button and title-colored masonry tiles outweighed due work. Delivered a resume/due section, quieter discovery action and a scrolling topic list that renders visible rows on demand. Keep deck counts, topic mastery, search, lane filters and existing grading intervals. Next test answer reveal, button and swipe grading, large text and no-due states. |
| Card creation, management and bulk generation · CardsScreen, CardSheet, CardGenScreen | Keep manual cards, source ownership, flagged and parked filters, progress and pause/resume. Next explain Flag and Park at point of use. In bulk generation show destination, local/remote route and estimated work before Start. Test returning from a card editor to the same topic. |
| Scout, chat history, drafts, research, approvals, citations and session usage · AskView, AskDialogs, AskScreen, ScoutAnswerView, SessionUsageView | The landing paragraph combined privacy, slash commands and background behavior. Delivered a shorter first question flow, wrapping suggestions and remote-data disclosure. Keep the explicit full-access explanation, queued directions, approval diff, cancellation and cited answers. The composer now shows source scope and approval mode for remote Scout. Retain history, usage details and export in chat actions. |
| Settings, Profile, model pickers, PDF download and Instagram access · SettingsView, SettingsScreen, ProfileScreen, ModelPicker, InstagramActivity | Profile repeats vault and model details available elsewhere. Delivered searchable setting groups and one accessible control per switch row. Browse now owns Vault details and lifetime activity counts. Settings owns key and model configuration. The separate Profile destination has been retired. |
| Dashboard, costs, health and session details · DashboardView, DashboardScreen, SessionUsageScreen | The cold dashboard briefly displayed zeros and “tracking is off” before receiving data. Delivered a snapshot guard. Preserve partial-history and unknown-cost labels. Overview now leads with pending captures, card saves and recovery copies when present. Keep detailed token accounting, exports and coverage in their existing drill-downs. |

## Rollout and acceptance

1. **Core navigation and readability — implemented in this branch.** Verify that Browse opens from Library, Capture opens the chooser, Review offers the correct due scope, Scout suggestions remain readable with the keyboard open, settings search retains contextual warnings, and cold Dashboard replaces loading with real values.
2. **Capture and retrieval — next release slice.** Test the title-first library row, then implement explicit capture status and per-tab return state. On a disposable vault, share a PDF offline, reopen Sparkbox, find it, reconnect and retry. Expect exactly one capture, an accurate destination, and Back to the prior search result. Keep Markdown compatibility and the Android share target.
3. **Primary knowledge system — after retrieval tests.** Unify reader actions, citation return, first-run setup and settings ownership. Prototype on compact and expanded windows. Use two panes for Browse and its selected note where space permits. Preserve selection when a foldable resizes. [Android adaptive list-detail](https://developer.android.com/develop/ui/compose/layouts/adaptive/list-detail)
4. **Accessibility and platform qualification — gate each slice.** On Android test TalkBack, Switch Access, keyboard traversal, light/dark, 200% text, landscape, gesture Back and reduced motion. Use at least 48dp targets. Test both display and semantics for loading, saved, disabled, retry and error states. On iOS use native tab navigation, sheets, Dynamic Type, VoiceOver and 44pt default controls. Preserve task names and data states across clients. [Android accessibility defaults](https://developer.android.com/develop/ui/compose/accessibility/api-defaults) · [Apple accessibility guidance](https://developer.apple.com/design/human-interface-guidelines/accessibility)
5. **Validate before expanding scope.** Recruit five people split between existing Obsidian users and people new to knowledge management, including someone who uses enlarged text or a screen reader. Observe first capture, retrieve yesterday’s source, explain local versus filed, review one card and inspect a Scout citation. Record unaided completion, wrong turns, median time and recovery. Proposed gate: at least four of five finish each task without coaching; everyone can identify where a capture is saved. Compare times with the baseline on the same device and fixture. No productivity gain has been measured yet.

Existing release gates still apply: usable Library within 291 ms, at most 1% janky frames while processing, and no lost capture after process death. Use the repository’s measurement protocol and disposable fixtures. [Release baseline](../../baseline.md)

## Verification on the installed build

Gradle completed `assembleDebug check assembleRelease`. The signed release updated the existing USB installation in place. On the phone, Library opened the capture chooser and vault folders. Review showed the due-card action. Scout displayed the shorter introduction and complete suggested questions. Searching Settings for “widget” exposed Home screen widget. Dashboard loaded Library overview and Back returned to Library. Light mode, 200% text, assistive input, interrupted writes and release performance gates remain device qualification work.


## Second implementation pass

Library, Review and Scout retain their detail stacks while the activity remains alive. Capture detail puts status and retry ahead of the preview. Library processing cards disclose individual steps on demand. Direct capture confirmation names its destination. On wide windows Browse shows a searchable note list beside the reader. Settings values can stack and card actions and annotation chips can wrap at large font sizes. Source readers expose Markdown editing from their navigation group.

Android 15 emulator checks used a disposable vault. An open reader survived a change from 1120dp wide to 360dp wide. At 200% text the quick capture sheet displayed its destination and Save action above the keyboard. Review’s empty state and Scout’s setup state were inspected at the same text size. An offline PDF capture survived force-stop, restart and reconnection with exactly one attachment and one inbox entry. This exercised local saving. AI processing, assistive technology and release performance require separate qualification.
